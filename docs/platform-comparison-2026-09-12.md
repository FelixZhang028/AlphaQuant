# 平台功能核查与竞品对照

核查日期：2026-09-12。依据本地代码、默认数据仓库和竞品公开官方资料。未登录竞品付费版本逐项实测；官网宣称代表产品公开能力，不代表所有套餐可用，也不证明运行质量。聚宽部分页面有地区访问限制，相关内容采用官方搜索索引和可读取指南。

## 结论

目前是基本连通研究流程的本地 A 股日频工作台，不能称为功能齐全、完成生产验收的主流量化平台。此前“第二阶段完成”指该阶段约定的代码和测试完成，不代表整个平台完成。测试通过也不等于真实全市场数据、长期运行与所有页面交互已验收。

已有：中文选股向导、规则/因子组合/Python 策略、AI 研究入口、数据检查、日频回测、成本和风控、因子 IC/分组/显著性/年度/衰减分析、样本外组合评估、网格优化、滚动样本外验证、历史结果比较，以及研究方案版本保存恢复。

## 最值得补齐的基础功能

| 优先级 | 功能与当前状态 | 为什么值得做 |
|---|---|---|
| 1 | 财务、估值、历史行业/市值、历史指数成分与退市证券数据：缺少完整的获取和更新闭环 | 用户目前不能像调用价量数据一样直接研究低估值、盈利质量、成长等常见思路。必须保留数据当时可知日期 |
| 1 | 默认真实数据覆盖：当前只有 9 只股票日线，范围 2024-01-02 至 2026-09-10 | 这是默认仓库现状，不是引擎的股票数上限；合成数据测试不能代替真实全市场研究验收 |
| 1 | 常用因子：随代码提供 10 个内置因子＋4 个 Alpha101；Alpha158/360 未接入 | 应先补估值、质量、成长等有数据支持的常用因子，不能只追求凑齐编号 |
| 1 | 因子评估结果库：单因子报告主要在点击评估的当前渲染展示；组合研究有会话缓存与 JSON 导出，未形成统一的持久化结果库 | 应保存因子版本、股票池、区间、处理方式、数据版本和完整指标，支持重开、比较和复算；这不同于已完成的策略方案版本管理 |
| 1 | 完整复现：已有配置快照和数据更新记录，但没有把所需数据版本、策略代码与因子定义版本完整冻结并一键恢复 | 相同方案在数据更新或自定义代码修改后不保证得到相同结果 |
| 2 | 后台任务：已有批量参数并行计算，但未见统一持久任务队列、取消、重启恢复、定时更新及完成通知 | 全市场计算耗时后，用户应能离开页面并回来查看；计算并行不等于任务管理 |
| 2 | 完整研究报告导出：部分 CSV/JSON 已支持，尚无统一中文可分享报告闭环 | 应把假设、数据条件、收益风险、验证结论与图表一起导出，便于复盘；这是产品实用改进，并非已逐家确认的竞品标配 |
| 2（上线多人使用前） | 用户隔离：方案按账号隔离，但不能据此认定回测记录、数据、自定义策略及执行资源均已隔离 | 当前适合本地个人工作台；面向公众前还需要完整权限及执行隔离验收 |

数据证据：本次默认 `runtime/market_akshare` 有证券主表、交易日历、基准、日线及更新记录；未发现 `universe_membership`、`security_exposures`、`delisting_settlements`。相关历史股票池和中性化代码可以读取规范表，但目前不能把“算法支持”说成“用户开箱可用”。

聚宽提供行情、财务、基本面与因子数据；米筐有按历史时点查询的财务接口，说明数据可用日期本身就是研究基础设施的一部分。[聚宽数据](https://www.joinquant.com/data)、[米筐股票数据 API](https://www.ricequant.com/doc/rqdata/python/stock-mod)

## 能力缺口，但不必现在全部追齐

- 分钟/Tick、多资产：当前主引擎围绕 A 股日频；不是增加一个频率下拉框或股票代码就完成支持。
- 持续模拟交易、真实执行：模拟交易界面此前主动移除，残留日线回放服务不等于盘中新行情驱动的持续模拟账户。若定位仅研究，可以暂缓；若声称支持交易落地，则需要补齐。[聚宽指南](https://www.joinquant.com/guide)
- 机器学习训练预测、模型版本管理、拖拽工作流：当前未形成一等功能。LLM 研究和按训练期 IC 定权不能等同于完整机器学习平台。BigQuant 已有相关产品能力，但这不是 A 股日频研究 MVP 的上线前置条件。[BigQuant AIStudio](https://sysubs.bigquant.com/wiki/doc/NzAjgKapzW)
- 专业风险模型与行业/风格收益归因：已有回归 Alpha/Beta、信息比率、跟踪误差和基础风险配置；这些不等于完整风格归因。米筐另有专门的 RQPAttr 产品。[米筐文档](https://www.ricequant.com/doc/)
- 社区、课程、分享生态与团队协作：目前的先验知识库不能等同于公开社区生态，可随用户规模发展。

不要重新列为“完全没做”的功能：因子组合、IC 显著性与衰减、相对绩效、波动率倒数/风险平价/均值方差组合、换手限制、参数并行和滚动样本外验证，代码均已有实现。其深度、真实数据适配和规模性能还应分别验收。

## 我们现在真正值得保留的特点

1. **围绕一个具体选股想法走完流程。** 从中文意图出发，查看实际规则、检查数据，再运行并读取报告。对使用内置模板的新手，有机会比先学习 API 的流程更省事。
2. **主动解释结果的适用范围。** 将跑赢基准、回撤、是否做过样本外验证解释为人能理解的问题；不把正收益、记录数量自动称为策略有效。
3. **在数据不足时尽早阻止误用。** 数据预检、缺少历史暴露时明确报错、成本和成交限制可追查。这是已实现的设计特点，不是证明比竞品计算更准。
4. **本地方案可控。** 方案、规则和报告能保存在用户自己的工作台；但竞品也提供本地 SDK 或私有部署，因此不是独占优势。调用外部数据或 LLM 时也不能承诺全部数据永不离开本机。

尚无对照用户测试、统一数据上的速度和准确性基准，因此不能有证据地说“整体更好”“回测更准”“AI 更强”。建议让新手在同一个任务上试用，比较首次成功时间、失败率、无需协助完成比例，再决定可以对外宣传哪些领先点。

## 推荐顺序

先补数据闭环与常用因子 → 保存因子评估和完整复现 → 后台任务与报告交付 → 用真实用户验证新手体验。机器学习、工作流和实盘按产品定位后置，不应先增加页面数量。
